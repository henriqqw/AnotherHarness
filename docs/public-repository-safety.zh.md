# 公开仓库安全

[English](public-repository-safety.md) | 中文

本参考文档定义哪些内容永远不得进入公开的 AnotherHarness 仓库，以及阻止其进入的检查。所有提交、推送或写入 issue、拉取请求、提交信息或 CI 日志的内容都对全世界可读且永久存在：删除的行仍会留在 Git 历史、fork 与缓存中。

## 永不发布

- **机密：** 任何提供商的 API 密钥、令牌（包括 GitHub 的 `ghp_`、`gho_` 与 `github_pat_` 令牌）、密码、OAuth 客户端密钥、cookie、会话标识符、私钥与证书、签名材料、携带令牌的 webhook URL，以及含凭据的连接字符串。
- **来自真实机器或账户的标识符：** 账户、用户、组织、租户与项目 ID；机器名；IP 与 MAC 地址；硬件序列号；设备 ID；以及遥测或匿名身份 ID。
- **个人与用户数据：** 真实姓名、电子邮件地址、用户名、主目录路径、电话号码、邮寄地址、聊天记录、录制的会话，以及显示上述任何内容的截图或录像。
- **私有项目：** 来自其他仓库、委托项目（包括安全测试）或私人工作的代码、文件名、路径、主机名、发现、目标与客户数据。
- **本地环境数据：** `.env` 的内容、含真实凭据的 MCP 配置、Harness 主目录、设置与凭据存储、shell 历史以及崩溃转储。

## 必须遵守的做法

1. 只使用占位符：来自环境的 `DEEPSEEK_API_KEY`、`<your-api-key>`、`example.com`、`user@example.com`、`/home/user` 与 `C:\Users\user`。测试密钥必须明显是假的，例如 `sk-test-0000`。
2. 将机密保存在 Git 之外：放在被 gitignore 的根目录 `.env`、环境变量或操作系统钥匙串中。只提交带占位值的 `*.example` 文件。
3. 每次提交与推送前，检查 `git diff --cached` 中每一行新增内容，搜索密钥模式（`sk-`、`ghp_`、`gho_`、`github_pat_`、`AKIA`、`PRIVATE KEY`、`password`、`token`、`secret`）、主目录路径与真实用户名。
4. 在提交录制的会话与快照前，清除其中的密钥、路径、用户名与私有内容。
5. 将私人笔记、计划与调研放在被 gitignore 的 `.private/` 目录中，永远不要放在 `docs/` 中。
6. 不确定时，不要包含该内容，并询问维护者。

## 机密泄露时

立即停止并告知维护者。将该机密视为已泄露：吊销并轮换它，因为从 Git 中删除并不能撤销暴露。是否改写历史由维护者决定，绝不由 agent 决定。
